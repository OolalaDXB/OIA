## Utiliser Shyrka : commandes exactes

Tout se lance depuis `~/OIA`, sur `main`, avec le volume `Shyrka-corpus` déverrouillé.

```bash
# État complet : versions, chiffrement, mémoire, connecteurs, service, droits manquants
pnpm shyrka:executive doctor

# Parler avec Shyrka (mémoire active si le volume est monté et chiffré)
pnpm shyrka:parler                 # pousser pour parler
pnpm shyrka:parler -- --texte      # au clavier
#   « Retiens que … »  « De quoi te souviens-tu ? »  « page suivante »
#   « Qu'avais-je décidé pour SILLON ? »  « Que sais-tu de … ? »
#   « Corrige le souvenir 1a2b3c4d : … »  « Oublie 1a2b3c4d »
#   « Active le mode privé » / « Désactive le mode privé »

# Briefing
pnpm shyrka:executive run-once           # collecte réelle bornée (~30 s)
pnpm shyrka:executive brief              # briefing à l'écran (copie dans ~/.oia/shyrka-executive/briefs)
pnpm shyrka:executive brief --voix       # plus une synthèse courte, voix Aurélie
pnpm shyrka:executive brief --marquer    # ce briefing devient la référence « depuis »

# Retrouver
pnpm shyrka:executive cherche "Quel est l'état connu du cockpit ?"
pnpm shyrka:executive cherche "Qu'est-ce qui reste à valider ?"
pnpm shyrka:executive cherche "Quelles informations sont absentes ou anciennes ?"
pnpm shyrka:executive memoire lister | chercher <mots> | oublier <réf> | exporter <fichier hors dépôt>

# Missions et incidents
pnpm shyrka:executive missions list
pnpm shyrka:executive missions show eaffddbc      # preuves, périmètre, journal, diff
pnpm shyrka:executive missions refuser eaffddbc "motif"
pnpm shyrka:executive incidents list
pnpm shyrka:executive incidents ignorer <réf> "motif"
pnpm shyrka:executive notifications
pnpm shyrka:executive vues                        # JSON du contrat Lovable v1

# Contrôle
pnpm shyrka:executive pause | resume | stop
pnpm shyrka:executive service install | status | uninstall
pnpm shyrka:executive acceptance                  # recette : tests, persistance réelle, corpus réel

# Revenir en arrière sans perdre la mémoire (~/OIA reste sur main)
git worktree add ~/OIA-v9 3c3d2b9 && cd ~/OIA-v9 && pnpm install --offline && pnpm shyrka:parler -- --texte
pnpm shyrka:executive service uninstall           # retire le service ; mémoire et données conservées
```

## Limites

- **Purge physique** : `secure_delete` et l'optimisation de l'index effacent le texte du fichier de base (vérifié). En revanche, un **export ou une sauvegarde déjà écrits** gardent le texte jusqu'à leur suppression ou leur expiration (30 jours, ta décision). Le registre des oublis empêche seulement leur réactivation. Les instantanés APFS et Time Machine du volume hors-ligne ne sont pas maîtrisés par le code.
- Les filtres de secrets et de Swift sont des garde-fous par motifs, pas une preuve d'absence.
- Le service ne surveille que lorsque le Mac est allumé et en réseau, et le volume ouvert pour la mémoire. Il ne peut pas signaler sa propre extinction.
- Les deux autres défauts trouvés par le diagnostic ne sont pas corrigés : « la suite stp » n'est pas reconnu comme un accord, et « celle-là » / « celle ci » ne sont pas reconnus comme référence.
- Latences de la voix (transcription, génération, premier son, lecture) non mesurées : il faut le micro.
- `git pull --rebase` refuse de s'exécuter à cause de ta modification locale de `knowledge/generated/…`, que je ne devais pas toucher, ni remiser. Chaque push a donc été précédé d'un `git fetch` et d'une vérification d'écart nul.
- Chaque push sur `main` redéploie la console Vercel (`@oia/web` inchangé). Le push de la branche de mission peut avoir créé une Preview.
